Составлено 15.08.2026. Приложение: **SNR EduOS** для родителей, Expo SDK 54,
пакет/бандл `com.snr.eduos.parent`, аккаунт Expo `snreduos`, проект
`b4dbd5ca-95ba-4402-8dd6-3f18163e7f7f`.

> должен сделать человек. Команды приведены, чтобы их можно было запустить, а

## 1. Профили сборки (`eas.json`)

| | `preview` (было) | `production` (добавлен) |
|---|---|---|
| зачем | раздать своим на проверку | выложить в магазины |
| Android | **APK** — файл, который ставится прямо на телефон | **AAB** (app bundle) — единственный формат, который принимает Google Play |
| iOS | внутренняя раздача | сборка для App Store |
| канал обновлений | `preview` | `production` — обновления по воздуху для магазинной сборки не смешиваются с тестовыми |
| номер сборки | не трогается | **+1 автоматически** (`autoIncrement`) |

Команды (запускать по отдельному слову заказчика):

```bash
cd apps/mobile-parent && eas build --profile production --platform android
```

```bash
cd apps/mobile-parent && eas build --profile production --platform ios
```

## 2. Номера версий

Их два, и путать их нельзя:

* **Версия для человека** — `expo.version` в `app.json`, сейчас `1.0.0`.
  Её меняет человек, когда выпускает новую версию: `1.0.1`, `1.1.0`.
* **Номер сборки** — `versionCode` у Android и `buildNumber` у iOS. Магазины
  требуют, чтобы у каждой новой загрузки он был **строго больше** предыдущего,
  иначе загрузка отклоняется.

В проекте включён режим `appVersionSource: "remote"` — номер сборки хранится на
стороне EAS, а не в файлах репозитория. Поэтому **явные `ios.buildNumber` и
`android.versionCode` в `app.json` не нужны и вредны**: при удалённом режиме EAS
их игнорирует и предупреждает об этом. Правильный способ — `autoIncrement` в
профиле `production`, он и включён. Посмотреть или задать текущий номер:

```bash
cd apps/mobile-parent && eas build:version:get --platform android
```

## 4. Два документа, которых не хватает

Приложение уже умеет их показывать, документов нет.

1. **Пользовательское соглашение** (условия использования).
2. **Политика конфиденциальности** — без неё в магазины не пускают вообще, даже
   если приложение ничего не собирает.

Что нужно сделать заказчику:

1. Опубликовать оба документа по постоянным адресам — например
   `https://…/legal/terms` и `https://…/legal/privacy`. Подойдёт любой хостинг,
   лишь бы адрес открывался без входа в аккаунт и не менялся.
2. Прислать эти два адреса. Мы впишем их в `app.json` → `expo.extra`:
   `legalTermsUrl` и `legalPrivacyUrl` (сейчас там пустые строки).
3. Те же два адреса вписать в карточки Google Play и App Store Connect.

Пока адресов нет, обе ссылки — на экране входа и в «Профиль → Язык и
безопасность» — не молчат: они объясняют, что документ готовится и что за
подробностями нужно обратиться в школу. Как только адреса появятся, ссылки
начнут открывать документы **без новой сборки** — значение приезжает обновлением
по воздуху.

Текст документов мы не пишем: это юридическая ответственность школы.

## 5. Анкета о сборе данных — что отвечать

Обе консоли спрашивают одно и то же. Факты по нашему приложению:

* приложение собирает: **номер телефона родителя** (вход), **имя родителя**,
  **учебные данные ребёнка** (оценки, посещаемость, задания, сообщения);
* всё это привязано к личности и используется **только для работы приложения**;
* рекламы, аналитики и отслеживания **нет**: сторонних SDK для этого в проекте
  не подключено (в файле для Apple так и заявлено — `NSPrivacyTracking: false`);
* данные хранятся в базе школы (Supabase), третьим лицам не передаются;
* удаление аккаунта: аккаунт заводит и закрывает школа, из приложения удалить
  нельзя — приложение об этом честно пишет. В анкете так и указывать: удаление
  по обращению в школу.

## 8. Что мы делаем сами, когда заказчик даст своё

1. Вписываем два правовых адреса в `app.json`.
2. Запускаем `eas build --profile production` — отдельно Android и iOS.
3. Android: получаем `.aab`, отдаём заказчику или заливаем через
   `eas submit --profile production --platform android` (нужен служебный ключ
   Google Play).
4. iOS: сборка требует Apple Developer; загрузка — через
   `eas submit --profile production --platform ios` (нужны Apple ID и
   идентификатор приложения в App Store Connect).
