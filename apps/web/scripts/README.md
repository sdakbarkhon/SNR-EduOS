# Скрипты: что здесь лежит и как этим пользоваться

Заведено 26.08.2026. Читать перед тем, как что-то запускать.

Это **не часть приложения**. Ничего отсюда не выкатывается на сайт и не
запускается само по расписанию. Всё запускает человек руками, и всё работает
служебным ключом — то есть **проходит мимо всех правил доступа**. Ошибка здесь
не покажет сообщение об ошибке, она просто изменит данные.

---

## Главное правило: всегда указывать школу

Школ две, и почти все эти скрипты писались, когда была одна. Поэтому:

```
node --env-file=.env.local scripts/имя.mjs --school=<идентификатор> [--confirm]
```

Запускать **из папки `apps/web`**.

| школа | идентификатор |
|---|---|
| демо (витрина) | `a0a0a0a0-0000-0000-0000-000000000001` |
| боевая | `b0b0b0b0-0000-0000-0000-000000000001` |

Без `--school` скрипт выйдет с подсказкой и **не обратится к базе ни разу**.

Если указать школу, которой нет, — тоже выйдет. Если скрипт написан под
конкретную школу (в нём завязки на её группы, логины и даты), а вы укажете
другую — он **остановится с ошибкой**, а не применится молча не туда. Это
специально: молчаливое «сделал не там» хуже громкой остановки.

Проверка живёт в одном файле — `_school-arg.mjs`. Копий по скриптам нет.

## Три уровня опасности

### 🟢 Безопасные — только смотрят

Ничего не меняют, запускать можно спокойно.

| скрипт | что делает |
|---|---|
| `check-demo-rollback-dry.mjs` | показывает, что сделал бы ночной откат демо |
| `drain-rag-queue.ts` | разбирает очередь векторов для поиска по материалам |
| `fix-stage-durations.mjs` | считает длительности этапов |
| `restore-demo-stage-media.mts` | показывает, каких картинок не хватает этапам |
| `reset-superadmin-password.mjs` | меняет пароль суперадмина (данные школ не трогает) |
| `screenshots.ts` | обходит страницы и делает снимки экрана. Лежит в `scripts/` в корне репозитория, **не здесь**. К базе не обращается вовсе, вреда не несёт. Требует отдельной установки: `pnpm add -Dw playwright tsx` и `pnpm exec playwright install chromium` |

### 🟡 Пишущие — создают и меняют данные

Их большинство. Наполняют демо-школу: расписание, уроки, задания, оценки,
посещаемость, материалы, переписки. Чинят содержимое: подписи, картинки,
порядок вариантов в квизах.

**Что помнить:** почти все написаны под демо-школу и под конкретную неделю
(27 июля — 2 августа 2026, на которой демо заморожено). На боевой школе они
либо не найдут, что чинить, либо создадут что-то не то. Указывать `--school`
надо осознанно, а не наугад.

У большинства есть холостой прогон: без `--confirm` (у части — без `--apply`)
скрипт показывает, что собирается сделать, и ничего не пишет. **Смотрите на
вывод холостого прогона, а не на название флага.**

## Три скрипта с особым обращением

### `seed-demo-iteration4.ts` — пересоздание демо с нуля

Самый опасный файл в папке. **Вычищает десять хранилищ целиком** и удаляет
группы демо вместе со всем, что за ними тянется.

Раньше запускался одной командой `pnpm seed:demo-iter4` без единого
предупреждения. Строка из `package.json` убрана.

Теперь перед работой он **показывает живыми числами**, сколько файлов лежит в
каждом хранилище и сколько уроков уйдёт каскадом, а потом просит напечатать
руками:

```
ПЕРЕСОЗДАТЬ ДЕМО ПОЛНОСТЬЮ
```

Любой другой ввод — выход без единого действия. Подтверждение нельзя
заготовить заранее: если ввод идёт не с клавиатуры, скрипт откажется работать.

**Удаление файлов необратимо.** Версий у хранилища нет, восстановить нечем.

### `apply-migration.mjs` — применение миграции к проду

Единственный рабочий путь применения миграций (`supabase db push` на этой базе
запускать нельзя). Мешать ему нельзя, но и без предупреждения оставлять тоже.

Теперь показывает имя файла, версию, число строк, состав команд и шапку
миграции, после чего спрашивает «да». Флага «пропустить вопрос» нет
намеренно: по всему репозиторию этот скрипт не зовёт ни другой скрипт, ни
приложение, ни задание по расписанию — только человек.

### `snapshot-demo-baseline.mjs` — пересъёмка эталона демо

Перезаписывает эталон, к которому ночной откат возвращает демо-школу.

Опасность неочевидная: **если в демо что-то испорчено, порча станет новым
эталоном**, и откат начнёт её защищать. Поэтому перед записью скрипт
показывает, чем нынешнее состояние отличается от эталона, и просит
подтверждения.

## Чего не делать

- **Не запускать наугад.** Сначала холостой прогон, потом чтение вывода, потом
  флаг записи.
- **Не подставлять боевую школу скрипту, написанному под демо.** Он остановится
  сам, но если вдруг пройдёт — получите правдоподобный мусор.
- **Не запускать пишущее, пока идёт урок.** Автостарт и автозавершение работают
  каждую минуту, и правка на ходу столкнётся с ними.
- **Не удалять файлы `.tmp-*` и `.*-progress.json`** — в них лежат
  идентификаторы созданного при восстановлении.
